# Chapter translation UX plan

This proposal records the requirements and implementation baseline for chapter translation. Readers choose a panel or chapter action in the popup and check the active tab’s status. The reader view displays results over the images and provides controls while reading. The proposal retained the Indonesian Options interface and visual style that existed at the time. UI labels below are translated into English.

## Baseline from the existing implementation

| Area | Findings that inform the plan |
| --- | --- |

The popup also includes the global switch, provider and language settings, and one image permission prompt through `pendingOrigin`. | Reader | A trusted click triggers `PROCESS_PANEL`. ## Popup and two entry points

Use the existing popup width of about 354 px, constrained to the viewport, with 16 px of padding. Match the focus order to the vertical layout. At narrow widths, wrap text and stack buttons. Use buttons consistent with Options and give **Start translation** the most visual weight while the chapter preview is open.

1. Show **Manga Translator** and **Settings** in the header. Below, show the tab status and the global **Extension enabled** switch. When the extension is off, show **Enable the extension to translate**. For an empty tab or restricted URL, show **Open a manga reader in the active tab**. If the extension cannot connect or inject its content script, show a brief reason and **Retry** when available.
2. **Click a panel** offers **Enable click-to-select** or **Disable click-to-select**. Enabling this mode activates panel selection in the current document. Show **Click the panel you want to translate** in the reader and popup. The reader controls offer **Select a panel with the keyboard** when this mode is active. Selecting or cancelling a panel affects only that panel.
3. **Translate this chapter** opens a summary in the popup and uses the toolbar gesture to request reader access if needed. The summary shows the verified scope, the number of pages ready, and the selected provider and languages. For cloud providers, show **OCR text is sent to [provider]. This may use your API quota.** The chapter queue starts only when the user selects **Start translation**. Opening the popup, enabling click-to-select, opening the summary, and scrolling before selecting **Start translation** leave the queue idle. Starting a chapter preserves the current click mode. Turning off click-to-select during chapter translation keeps the chapter job running. While a chapter job is active, this row shows its status and **Pause**, **Resume**, or **Cancel** as appropriate.
4. **Provider and languages** uses the existing `ProviderSelect` and `LanguageFields` in an expandable area. Keep a one-line summary visible, such as **DeepL · Japanese to Indonesian**. Show image permission requests and configuration problems beside the action that depends on them. The chapter uses the settings in effect when the user selects **Start translation**. Changes to the provider, languages, or output settings apply to the next chapter. **Resume** uses the original chapter configuration. The user can update credentials for that provider in Options to recover the job.

If both entry points select the same panel, share the work when the image identity and output configuration match. Reuse valid patches or cached results. Chapter status, pause, and cancellation operate independently of panel actions. **Cancel chapter** stops the remaining chapter work and keeps results already displayed. After the runtime confirms cancellation, late chapter results may appear only if a valid independent panel request still needs them. Closing the popup or collapsing the reader controls keeps active jobs running. When reopened, the popup shows the job status for the corresponding tab and document.

## Discovery, progress, and results

Use **pages available** for unique candidates in the current chapter that are ready to process. Use **total pages** only when the page count and chapter boundary are reliable. Identify candidates using the document, a verifiable chapter identity, and each active image source. Exclude thumbnails, ads, placeholders, duplicate renderings, and images from the next chapter. For a generic reader layout, show **Chapter images available on this page**. The user scrolls manually to load lazy-loaded pages. Limit processing to the identified chapter or, if its boundary is uncertain, to the set approved at **Start translation**. A chapter change signal freezes the old job to prevent it from processing images from the new chapter.

| State | Copy and actions |
| --- | --- |
| Searching | **Finding chapter pages…**. Local discovery in the reader only collects candidates. If there are no candidates yet, show **No pages are ready to process. Scroll the reader to load pages, then check again.** Offer **Check again**. For unsupported layouts, show **This reader layout is unsupported**. |
| Ready, total known | **8 of 12 pages available**. **Start translation** processes the pages that are ready and accepts later pages as they appear within the same chapter. Show **Scroll to load more pages** if more pages still need to load. |
| Ready, total unknown | **8 pages available · Chapter total unknown**. Explain in the summary whether scrolling can reveal additional pages or whether processing is limited to the set available when the user starts. While the total is unknown, show counts without a percentage. |
| Running | Show **Translating chapter · 3 of 12 pages processed** when the total is reliable, or **3 pages processed · 8 available** when the total is unknown. The processed count includes completed, partial, and failed pages. Show the breakdown when the user opens the details. Keep **Pause** and **Cancel** available without opening the page list. |
| Waiting for pages | **5 pages complete · Waiting for more pages** when more pages still need to load. If the scope is uncertain and the queue is empty, show **5 available pages processed · Chapter total unknown**. Offer **Check for more pages** when the user needs to explicitly extend the scope. |
| Paused | **Paused · 3 pages complete**. Finish the active unit of work when safe. Start the next unit only after the user selects **Resume**. Show the reason if reader access or permissions block processing. Keep **Cancel** available. |
| Cancelled | **Chapter cancelled · 3 pages complete**. Results already available remain viewable. **Translate this chapter** opens a fresh summary and can reuse valid results. |
| Complete or partial | Show **12 pages complete** once every known page finishes successfully. If any work fails, show **9 complete · 1 partial · 2 failed** and **View issues**. A partial page contains usable results alongside untranslated dialogue areas. The issue list shows the page number when known, the reason, and **Retry** for eligible items. **Retry failed items** processes failed items or remaining work that can be retried safely and preserves successful patches. |
| Failed or interrupted | Examples include **Translation stopped · Provider quota reached**, **Check Settings**, and **Reconnect**. Preserve the status of completed items. If a provider issue affects every page, stop scheduling work until the user fixes the cause. After refresh or navigation, require a new **Start translation** action for the new document and ignore responses from the old document. |

## Reader controls and recovery

- Keep the shadow DOM and noninteractive layer. Replace the permanently wide status box with a bottom-corner bar that expands to about 320 px at most. The collapsed view shows **Translation status** with a short progress summary. The expanded view shows status, relevant actions, and an issue list as needed. Respect the viewport's safe area, use 44 × 44 px touch targets for primary controls, leave about 8 px between targets, and wrap controls at narrow widths. Offer **Collapse** when the bar covers dialogue or navigation. Scrolling, links, and reader gestures work normally outside the controls. Click-to-select intercepts only valid panel selections.
- Once the document has results, offer **Original** and **Translation** in a control labelled **Image view**. Use pressed-button or radio semantics to indicate the active choice. Switching views affects only the results layer. When **Original** is selected, jobs can continue and store new patches while keeping them hidden. If there are no results yet, show **No translations yet** when the user opens the details. The completed page count represents results that can be displayed again in that document. Because the overlay evicts patches beyond its 32-patch limit, chapter translation needs to restore patches when readers return to earlier pages.
- Request image origin permission through an explicit popup action labelled **Allow image domain** and show the domain. After the user grants permission, offer **Retry** for the panel or **Resume** for the chapter. If permission is denied, let the user select **Skip page** in the issue list or manually select the visible area if the image can be captured. If image fetch still returns HTTP 403, show **Couldn't fetch the image. Select the visible panel area.** Settings for provider access have their own actions and status in Options.
- Attach capture recovery to the failed panel, including entries in the chapter issue list. **Select visible area** asks the user to select the area again after confirming it is fully on screen and clear of reader overlays. Support dragging, selecting opposite corners with two clicks or taps, and keyboard selection through the same control. If the user switches tabs, zoom or scroll changes the geometry, something covers the area, or tab permission is lost, restore the bar and focus. Show the reason and an action such as **Return to the reader tab**, **Select the area again**, or **Open the popup to reconnect**. A new capture requires a new area selection. Crop the temporary full screenshot locally and use the selected area as the pixel source for OCR. Chapter mode requires user action for tab capture, scrolling, and permission prompts.
- If the reader tab becomes inactive, pause chapter scheduling and show **Paused · Return to the reader tab**. On return, offer **Resume** if the document and access are still valid. The popup in another tab shows only that tab's status. Discard an in-progress capture if the tab or capture context changes. Turning the extension off globally stops work and hides overlays. After turning it back on, the user must start the chapter again.

## Options, accessibility, and privacy

- Keep all Options fields and behavior. **Translation** includes provider, source and target languages, API key, controls to remember or remove the key, permissions and connection testing, LLM model, DeepL plan, and Azure region. **Local processing** includes OCR language, dialogue order, runtime, inpainting, and detection prefetching. **Advanced settings** includes context, previous panels, series title, glossary, font, font weight, bubble padding, line height, diagnostics, and cache clearing. Keep the save button and feedback easy to find. Show errors near the relevant action or field and preserve form values while the user fixes them.
- BYOK uses a password input in Options and session storage by default. Store the key locally only when **Remember API key** is enabled. The broker reports only whether the key exists. Restrict keys to trusted contexts and omit them from chapter status, reader messages, and logs. Cloud providers receive OCR text, language settings, and any enabled text context if the provider supports it. Pixels stay local. Show image and provider permission requests for the required origins. [Credentials](../src/storage/credentials.ts) · [Privacy and permissions](../README.md#privacy-and-permissions)
- Use native controls, visible and unobstructed focus, text contrast of at least 4.5:1, and clear status labels. While **Select a panel with the keyboard** is active, list detected areas in the reader with labels such as **Page 2 · Panel 3** and use Enter to select. If a panel map is unavailable, show instructions for a selection box the user can adjust with the arrow keys and confirm with Enter. Escape cancels selection, closes the focused details, or cancels an active panel job when focus is on its panel action. Return focus to the triggering control when the user exits selection or details. Chapter actions have a dedicated cancel button. Avoid intercepting keystrokes in site inputs or controls.
- Keep button nodes mounted during status updates to avoid the focus loss caused by `replaceChildren()`. Use `role="status"` for important transitions and aggregate counts, and `role="alert"` for failures that need immediate attention. When the user opens the details, offer **Read translated text** in dialogue order. The canvas label currently identifies only the panel. **Original** hides the accessible results associated with the translation layer. Honor `prefers-reduced-motion` and avoid announcing each OCR stage.

## Acceptance tests

Use the existing fixtures and mock provider, adding chapter variants as needed. Test Chrome's permission prompt manually using an unmodified build. The E2E tests at the time used a copy with host permissions for cases that require a grant. [Smoke E2E](../tests/e2e/extension-smoke.e2e.ts) · [Reader fixture](../tests/fixtures/reader.html)

| Scenario | Expected result |
| --- | --- |
| Panel entry point | Enable click-to-select, click one panel, and verify one job and one patch. Clicking a gutter offers area selection. Opening the chapter summary without selecting **Start translation** produces zero chapter translation requests. |
| Chapter entry point | With click-to-select off, open the summary and select **Start translation** once. Chapter translation runs with click interception still off. Repeat with click-to-select enabled and the same panel in the queue. The provider receives at most one job for the same result. |
| Discovery | Test fixed-length, lazy-loaded, and empty chapters, changes to `picture/currentSrc`, thumbnails, and layouts that load the next chapter. Unique counts are accurate, unknown totals have no percentage, and the new chapter stays outside the job scope. |
| Job lifecycle | Close and reopen the popup, pause, resume, switch tabs, and cancel while the provider is slow. Status and counts stay consistent, scheduling stops while paused, and successful patches stay visible. After cancellation, refresh, or a chapter change, late responses leave the new source intact. |
| Partial results and failures | Force one page to fail, another to translate only some of its dialogue, and the provider to hit its quota. Verify counts and reasons. Scheduling stops if the cause affects all pages. Retrying processes only items with unresolved issues. |
| Capture and permissions | Test denied and granted image permissions, HTTP 403, a tab switch during capture, an obstructed area, and zoom or scroll changes. Capture requires explicit area selection. Invalid captures reach neither OCR nor the provider. The overlay recovers, and capture succeeds after a valid reselection. Restricted tabs or tabs without a reader show a next step. |
| Results and reading space | Create more than 32 patches, return to the first page, and switch between **Original** and **Translation** while another job finishes. Earlier results can be displayed again, **Original** stays selected when a job finishes, and the canvas and controls leave scrolling and links outside their targets usable. Test a 320 px popup and 200% zoom. |
| Keyboard and screen reader | Complete the popup, chapter, panel, and capture flows without dragging, then test with a screen reader. Focus persists through status changes, Escape restores focus, announcements cover meaningful status changes, and translated text is readable in dialogue order. |
| Settings and security | Load an older configuration, save each group of fields, and test local and cloud providers. Verify that provider and image permissions are independent, keys stay in trusted contexts, and the provider receives only the text payload allowed by the settings. |
