# Manga Translator implementation plan

Build a WXT, TypeScript and Svelte extension for Chromium MV3. Activate the reader in the current tab, click a panel, run local OCR, translate ordered text with the selected provider, erase source glyphs, then display a typeset patch over the original image. Escape cancels selection or an active job. The reader can reveal the original or clear individual patches.

First release targets visible, loaded top-frame `<img>` and `<picture>` elements in HTTP(S) readers. Use natural image dimensions and click location. Prefer classical gutter detection and use an optional panel detector where it helps. Offer manual area selection when boundaries are ambiguous. Source OCR covers Japanese, Korean, Chinese and English. Full-chapter automation and cross-origin frames sit outside the first release.

## Module and permission boundaries

[ARCHITECTURE.md](ARCHITECTURE.md) and [shared contracts](../src/types/contracts.ts) define the entry points, routing and TypeScript shapes. Use WXT's `src/entrypoints` for the reader content script, background service worker, Svelte Popup and Options, and the bundled offscreen page. Keep domain logic in `src/core`, storage in `src/storage`, and versioned runtime schemas in `src/messaging`. Verify the generated Chromium MV3 manifest and packaged entry points in Phase 0. [WXT entry points](https://wxt.dev/guide/essentials/entrypoints.html)

| Context | Responsibilities and boundaries |
| --- | --- |
| Reader content script | Inject only on activation in the top frame and isolated world. Track loaded images, `currentSrc`, layout and image revisions. Send typed `PREFETCH`, `PROCESS_PANEL` and `CANCEL` operations. Display anchored panel boundaries, per-image patches and job state in an isolated UI. |
| Background service worker | Register handlers synchronously. Validate runtime schemas, select the provider, enforce permissions and enqueue jobs. Route by tab, top frame and Chrome document ID. Bind selection and results to the same image revision. Only trusted extension pages can change credentials or provider settings. |
| Offscreen document and dedicated worker | Use a bundled offscreen page with the `WORKERS` reason. Use the architecture's temporary IndexedDB blob transport and transfer buffers on the worker link. Keep decode, crop, detection, OCR, mask, erase and layout local. Keep provider secrets in the broker. Probe Chrome Translator availability in an extension document. |
| Popup and Options | Activate the reader, choose source and target languages and select one provider. Show which remote provider receives text. Request exact endpoint or denied image-origin permission from an explicit user gesture. Display credential presence and sanitized connection status. |

Register `activeTab`, `scripting`, `storage` and `offscreen` as needed by the corresponding entry points. Require no install-time site hosts. The background can read images covered by `activeTab` or a user-granted exact image origin. Validate the fetched source URL, redirect policy, MIME type and size before handing bytes to the local worker. Request only the selected provider host and the specific image origin when needed. Chrome host permission constrains origins, so the broker must enforce provider table routes and must not expose a general fetch operation. On an unreadable image or denied permission, leave the reader image intact and return an actionable error. [Chrome activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab) · [Cross-origin requests](https://developer.chrome.com/docs/extensions/develop/concepts/network-requests)

Use an authorized top-frame port for reader traffic and a separate typed settings protocol. Check Chrome sender properties and the live document and image revision on each request and result. Accept only bounded finite geometry and payload lengths. Keep frames and image blobs out of provider adapters. Return panel maps, progress and WebP/PNG patch data through the extension channel. Keep `TranslationRequest.segments` ordered and validate the `TranslationResult` ID set before rendering. Forward optional textual context only when enabled. On Escape, disconnect, navigation or source replacement, abort fetches, cancel queued work, discard late inference output and dispose temporary blobs. Keep credentials in trusted-context storage and exclude keys, transcripts and images from diagnostic logs. [Chrome messaging](https://developer.chrome.com/docs/extensions/develop/concepts/messaging) · [Chrome storage](https://developer.chrome.com/docs/extensions/reference/api/storage)

Use the shared `ImageDescriptor`, `PanelRegion`, `TextRegion`, `OCRResult`, `TranslationRequest`, `TranslationResult` and `RenderedPatch` types. Store panel selection and patch anchors in normalized intrinsic image coordinates and OCR polygons in local crop pixels. Account for `object-fit`, `object-position`, clipping, DPR and responsive resize. Repaint patch anchors on layout changes. Apply a result only while its job and image identity match. Revoke generated URLs and clear stale patches when the reader replaces an image.

Package ONNX Runtime Web, its matching WASM and ESM support files, model weights, dictionaries, fonts and worker code. Start with a static dedicated worker, the `wasm` execution provider, `ort.env.wasm.numThreads = 1`, `ort.env.wasm.proxy = false` and an explicit package-local `wasmPaths` mapping. Use extension-page CSP `script-src 'self' 'wasm-unsafe-eval'; object-src 'self'; worker-src 'self'`. Probe WebGPU separately and fall back to WASM if the browser or graph requires it. Extension code, WASM and ONNX load from packaged URLs. Build-time downloads and browser-managed Chrome Translator packs provision assets. Image processing and Chrome Translator inference run locally. Cloud translation sends text to the one selected provider. [ORT Web flags](https://onnxruntime.ai/docs/tutorials/web/env-flags-and-session-options.html) · [MV3 extension security](https://developer.chrome.com/docs/extensions/develop/migrate/improve-security)

The detector YAML SHA-256 is `98069072e1b6b37d727fd9d9f11725faa46d6ea0de012f2ed26caea011c37699`. Match the reference preprocessing explicitly because detector resize defaults differ between the export YAML and the PaddleX predictor.

1. **Detection.** Use the PaddleX standalone PP-OCRv5 mobile detector policy as the first parity target. Decode to BGR, cap the longest side at 960 before rounding each dimension to the nearest 32 with a 32-pixel minimum, and use bilinear resize. Apply `(pixel/255 - mean[c]) / std[c]` in model channel order using mean `[0.485, 0.456, 0.406]` and standard deviation `[0.229, 0.224, 0.225]`. Pack float32 NCHW into `x`, opset 11. Read the rank-4 sigmoid probability map from `fetch_name_0`. Use DB contours at 0.3, mean box score at least 0.6, at most 1,000 candidates and unclip ratio 1.5. Obtain the minimum-area quads, discard undersized or degenerate candidates, clip and map using independent x/y scales. Keep any tiling for tiny text behind a fixture gate and deduplicate overlap in panel coordinates. [PaddleX detector preprocessing and DB](https://github.com/PaddlePaddle/PaddleX/blob/develop/paddlex/inference/models/text_detection/processors.py) · [Detector predictor defaults](https://github.com/PaddlePaddle/PaddleX/blob/develop/paddlex/inference/models/text_detection/predictor.py)
2. **Recognition.** Perspective-warp each quad. Feed BGR float32 `x[1,3,48,W]` at height 48 with proportional width, bilinear sampling, `(pixel/255 - 0.5) / 0.5` and right padding of literal zero after normalization. Start with width `max(320, ceil(48 * cropW / cropH))` capped at 3200. Split abnormally long regions before warping if the cap distorts text. These graphs use opset 7. Read softmax probabilities from `fetch_name_0[1,T,C]`. Build labels as a blank at index 0, the exact YAML array, then one ASCII space. Assert `C = entries + 2`. Greedy CTC takes the argmax per timestep, collapses consecutive identical indices before dropping blanks, then joins the labels. Score retained timesteps using their mean probability. [PaddleX recognizer preprocessing and CTC](https://github.com/PaddlePaddle/PaddleX/blob/develop/paddlex/inference/models/text_recognition/processors.py)
3. **Reading order.** Keep line quads from unwarped panel space. Group nearby compatible lines into dialog blocks. Handle horizontal text left-to-right within a line and top-to-bottom across lines. Group vertical Japanese columns top-to-bottom within columns and right-to-left across columns, with a source-layout override for ambiguous cases. Evaluate upright and 90°/270° rectification strategies on vertical and rotated fixtures, including stacked upright kana. Treat furigana as a separate region and suppress it only where fixtures support the rule. Preserve mixed Latin text in Japanese and Chinese mode. Use the configured reading-order override when geometry is ambiguous and omit uncertain text from destructive cleanup. Calibrate thresholds per recognizer on comic fixtures. [PP-OCRv5 language support](https://paddlepaddle.github.io/PaddleOCR/latest/en/version3.x/algorithm/PP-OCRv5/PP-OCRv5_multi_languages.html)

## Six translation adapters

Use the existing `ProviderId` and `TranslationRequest` contracts. The broker selects only the enabled adapter. Each adapter maps language tags, batches within its text limits and returns one result per ordered segment ID. For Gemini and OpenAI, constrain the response to JSON with the ordered IDs. Disable tools and treat source text as data. Reject duplicate, missing and extra IDs. Keep optional text context behind explicit settings. An unresolved OCR auto mode should request a source language when the model or provider cannot resolve the script safely.

| ID | API and authentication |
| --- | --- |
| `chrome` | Chrome Translator uses a document-context API and requires no key or provider host permission. Query `Translator.availability()` for the pair. Test first-run `Translator.create()` and its download progress from an explicit gesture in Options when browser activation is required. Probe in the offscreen document after setup. If this context cannot create or use the translator, keep the local adapter in an activated extension document or report capability unavailable. For cloud APIs use HTTPS POST, a deadline, cookies omitted and redirects disabled. Send text only after OCR completes for a live job. On revocation, cancellation, unavailable language, 429, timeout or malformed response, report a typed error and keep source art intact. Preserve `Retry-After` and leave potentially billable retries to a user action. A failing provider does not send text to another one. The install contains zero built-in credentials.

## Erase, typeset and composite

Start with a local glyph mask on each accepted OCR line. Estimate foreground polarity and background from nearby pixels, threshold using local contrast, then retain components close to the line and dilate modestly for outlines. Bound cleanup to the OCR area or manually adjusted dialog region. Preserve bubble contours, screentones and unrelated art. Fill flat regions using a robust neighboring color and use a local CPU inpaint routine for small textured masks. Return a cleanup error and preserve the source image when the mask would damage unrelated art. Check exact pixel preservation outside the allowed patch mask and text before compositing.

Fit translations within each block's safe area with bundled licensed fonts and appropriate script coverage. Segment words or graphemes using `Intl.Segmenter` where suitable, use CJK line-break rules, and measure actual text advances on the canvas after fonts load. Use target-language direction, explicit line spacing and a readable user-adjustable minimum size. Report layout overflow and preserve the source image. Test font loading in the actual packaged worker. If worker font support varies, keep layout and drawing in the extension offscreen page and feed it prepared local raster and mask data.
